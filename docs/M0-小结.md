### 计时口径说明（必须如实声明）

**本次执行不适用「人工版 5 天」的耗时基准。** 原因：

1. 本阶段采用 AI 并行施工模式（后端起 P1/P2/P3、运维起 P4/P5 并行），
   与人工版「逐日串行」的时间结构不可直接对比；
2. 本阶段最大的时间消耗**不在编码，而在本机环境从零搭建**：
   Go/Git 安装受 GitHub 不可达影响需绕镜像、PostgreSQL 需自备绿色版、
   沙箱对后台守护进程的强杀约束需要重新设计验收脚本形态。
   这些均非 M0 计划预算内的活动；
3. 因此**有效工时无法与「5 个工作日」直接闭合**，
   强行填一个数字会给出虚假的偏差率。

→ **不计入偏差率判断**，避免用一个不成立的基准推导出虚假的结论。
如技术负责人需要真实工时，建议以「环境就绪后的编码+验收净耗时」单独记录。

## 二、各任务偏差与偏离说明

| 项 | 偏差/偏离 | 处置 | 是否已获批准 |
|----|-----------|------|--------------|
| 迁移文件命名 | 规格写 `0001_init.sql` + `0002_*.down.sql`，实际用 `0001_init.up.sql` / `0001_init.down.sql` | golang-migrate 要求同版本 up/down 成对，否则 `down-all` 无法配套执行 | 已获技术负责人 2026-09-25 裁决采用成对命名 |
| `timeline.created_at` | V1.0 原文该表无此行 | 依 ADR-003「全表补 created_at」补上，使原文自身不一致处自洽 | 已获裁决「全部保留」 |
| `correlation_rules` 索引 | V1.0 原文该表无任何索引 | 补 `UNIQUE(name)` + `(enabled)` 索引 | 已获裁决「全部保留」 |
| 数值区间 CHECK | V1.0 原文无 | `correlation_score` / `confidence` / `weight` 加 `>=0`、`<=1` 防御性约束 | 已获裁决「全部保留」 |
| `incident_alerts(alert_id)` 索引 | V1.0 原文无 | 反查用索引 | 已获裁决「全部保留」 |
| 迁移版本号跳号 | 冻结约定写「后续只能新增 0003/0004」，但当前只有 0001 | 保留 `0003` 起编号空间；`0002` 为空号 | 无需动作，不影响功能 |
| `.editorconfig` 增 `[*.ps1] charset = utf-8-bom` | 规格未要求 | 修 Windows PowerShell 5.1 按 ANSI 解析无 BOM UTF-8 导致的中文假错（脚本原本无法执行）。**2026-09-25 已二次实证**：AI 自己重写的 `pg_init.ps1` 又踩同一坑 | **待技术负责人确认** |
| `.golangci.yml` 的 `errcheck.check-blank` 改 `false` | 规格未要求，且上一轮 AI 自行设为 `true` | 原设置导致 4 处官方推荐写法（`_ = x.Close()`）被误报，lint 必红 | 本轮修复，详见总验收报告 §八 |
| `web/tsconfig.node.json` 改 `declaration`+`emitDeclarationOnly` | 规格未要求 | 原设置违反 TS project references 规则（`TS6310`），**CI frontend job 原本必红** | 本轮修复，详见总验收报告 §八 |
