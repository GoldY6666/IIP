## 〇、M6 完成定义（DoD）

1. **证据可判可信度**：`evidence.confidence` 不再全空 ——
   采集器给出**有依据的**置信度，且**给不出时必须留空**（不得填 1.0 充数）；
   前端能区分「未评估」与「评估为低」。
2. **trace 证据可用**：至少一个 trace 数据源接入，`type='trace'` 的证据
   能采到、能落库、能展示（**不新增迁移** —— 见 §1.2）。
3. **部署形态有截图证据**：`docker compose --profile app up -d` 之后，
   用**真浏览器**打开一个地址完成「列表 → 详情 → 处置」并截图存档
   （收掉 M5 的 OPEN-M5-8）。
4. **鉴权不再是「仅供内网」**：UI 部署形态有明确的访问控制，
   `deploy/README.md` 里补上「V1.0 仅供内网/演示环境」的标注（收掉 OPEN-M5-1）。
   > **2026-10-07 更正**：S4 落地后该标注**保留、不移除**。
   > 关闭 OPEN-M5-1 的是「无访问控制」这个事实，不是「可以公网暴露」——
   > 静态 token 只挡误连，不等于多因素认证。原句「可移除」是错的。
5. **M4/M5 欠账归零**：`decisions.md` 的 OPEN 登记册与各里程碑报告**账目一致**
   （`OPEN-M4-1/2/3` 已登记；`§4.8` 类条款在 M5/M6 均不再是 NOT DONE）。
6. **不回归 + 质量达标**：五条验证链路（业务闭环 / 宿主全栈 / 容器 / 静态 / 真库）
   0 失败；真库门禁 **SKIP=0**；`golangci-lint` rc=0 无 `nolint`；
   前端 `tsc` / `vite build` / `vitest` / `e2e` 全 rc=0。

> **第 6 条的「SKIP=0」是硬要求**：真库门禁出现 SKIP 等于「这一条根本没验」。
> M5 遗留的 `TestHandlerAllowsSymlink…` 那个 SKIP 必须在 M6 内消除。

### 1.2 关键发现：`trace` 不需要新迁移

M4 报告把 OPEN-M4-2（无 trace 采集器）写得像要改表，**实际不需要**：

```sql
-- migrations/0001_init.up.sql
CONSTRAINT chk_evidence_type CHECK (type IN
  ('metric','log','trace','deployment','config_change','historical'))
```

`trace` **早已在 CHECK 约束内**，`idx_evidence_type` 索引也已覆盖。
缺的**只是采集器**（没有任何代码往这个值写）。
→ M6 实现 trace **零迁移**，直接写新采集器即可。

> 这一条值得单独记：**「以为要改表」与「真的要改表」差一次读schema**。
> 与 M4 的「`0005` 加了 tasks 表导致 `表数=8` 断言漂移」同源 ——
> 凭印象估工作量会多算一整个批次。

### 1.3 `confidence` 的现状与约束

- 列定义：`confidence DECIMAL(5,4)`，可空，
  CHECK 约束是 `confidence IS NULL OR (0 <= confidence <= 1)`。
- M4 起的实测：**全表为空**（容器链路有专门断言「非空条数=0」守着）。
- 前端已按 `number | null` 处理，null 显示「未评估」。

**M4 留空是对的**：填一个数必须对应「这条证据有多可信」的**可复核判据**，
而 M4 的采集器只做「采到/采不到」，没有评估能力。
**M6 要做的是给出那个判据，而不是随手填个 0.8。**

## 四、S1 设计要点：RCA 与 confidence

### 4.1 「置信度」必须是可复核的，不是拍出来的

填 `confidence` 前必须先回答：**这个数从哪来？** 三个可接受的来源：

| 来源 | 例| 复核方式 |
|------|---|---------|
| **来源自带** | Prometheus 样本的置信区间、Loki 的命中条数占比 | 回到原始数据源可验 |
| **规则命中** | 「错误量 5倍突增」⇒ 高；「仅有 1 条样本」⇒ 低 | 规则本身可读、可测 |
| **覆盖度** | 5 类证据里命中 4 类 ⇒ 支撑强；命中 1 类 ⇒ 弱 | 计数可核对 |

**明确禁止**：凭「这条证据看起来很重要」填数。
**给不出上述任一来源 ⇒ 必须留空**（沿用 M4 的裁决：留空 > 假装确凿）。

### 4.2 落库与展示

- 写入前用与 `Validate()` 同一套区间校验（`0 <= c <= 1`），
  越界视为**采集器缺陷**（与 M4 的 `timestamp` 规则同档：给不出就跳过，不兜底）。
- 前端把「未评估」与「评估为 X」**视觉上分开**——
  M5 已把 null 显示为「未评估」，M6 要确保**低置信度不会被误读成「未评估」**
  （那是反向的另一个错）。

### 4.3 必须验的（否则等于没做）

1. 同一事件多次采集，`confidence` 随证据强度**变化**（不是常量1.0）。
2. 无来源可依的证据类型**仍然留空**。
3. 越界值被拒（或按规则钳制）且**不静默写入**。
4. 前端「未评估」与「低」两种态**截图可区分**（沿用 F7 的像素断言手法）。

## 五、S2 设计要点：trace 采集器

### 5.1 定位

沿用 M4 三采集器的全部硬约束：
- **`timestamp` 是证据自身的时间**，不是采集时刻（ADR-003）；
- 单个采集失败**不阻断**其余；全失败才算任务失败；
- 超时 5s；`IIP_EVIDENCE_*_ENABLED` 开关**打开必须真的注册**
  （M4 缺陷二的教训：不许再出现死配置）。

### 5.2 零迁移

见 §1.2 —— `trace` 已在 CHECK 约束内，**不新增迁移**。
若实现中真的需要改表，**先回来改本章**。

### 5.3 默认关闭

新增 `IIP_EVIDENCE_TRACE_ENABLED`，**默认 false**，理由同 M4 的 K8s 采集器：
**写一个接不上真实数据源的采集器，比不写更危险**。
只有 mock server 单测证明解析与降级逻辑正确，不声称能接真集群。

以下四条已于 **2026-10-05 由禹「开始 M6」时裁定采用默认路线**，不再是待定项。

**若与禹的本意不符，改本节即可**，代码会跟着改。

| # | 问题 | **裁定（已生效）** | 不选另一方案的理由 |
|---|---|---|---|
| 1 | S4 鉴权强度 | **只做「环境变量注入静态 token」**：服务端校验请求头，前端从运行时配置读取并带上；**不做登录页** | 登录页会把 M6 从数天拉到 2 周以上，且它需要会话管理、注销、过期续期一整套配套设施，收益（本地/内网部署场景）不足以支撑成本 |

## 九、S4 实现裁定：token 怎么下发（2026-10-05 追加）

§八 裁定 1 定了「只做环境变量注入的静态 token」，但**没定token 怎么到达浏览器**。
这一条是实现前必须补的裁定 —— 补在手册里而非代码里，依据仍是 §2.1 的纪律。

### 9.1 三个候选与取舍

| 方案 | 做法 | 结论 |
|---|---|---|
| **A. 复用 `__IIP_UI__` 注入** | 把token 塞进已有的运行时配置注入块 | **否决**。`web/src/uiconfig.ts` 明确约定「注入内容不含任何密钥」，塞进去等于推翻自己的契约，且该块是页面可见的明文 |
| **B. 登录页 + 会话** | 完整 auth 流程 | **否决**。§八 已裁定不做登录页，理由（成本 2 周+）依然成立 |
| **C. 新增轻量会话端点** | `GET /api/v1/auth/session` 返回 `{auth_required, token}` | **采用**。端点本身在豁免名单里，仅此一个 |

### 9.2 三条路径豁免（与 §8裁定的边界）

| 路径 | 是否鉴权 | 理由 |
|---|---|---|
| `/api/v1/*` | **是** |业务数据面 |
| `/healthz` | 否 | compose healthcheck 依赖，且探针不可能带自定义头 |
| `/api/v1/auth/session` | 否 | 前端取token 的唯一途径；拦掉即死锁 |
| 静态托管与其余 | 否 | 不是数据面 |

### 9.3 两条实现细则（值得写下来，避免后人「顺手改坏」）

1. **默认关是契约，不是默认值**：`IIP_AUTH_TOKEN` 为空 ⇒ **完全不开鉴权**，
   保证 M5 既有 `docker compose --profile app up` 用法与全部既有验收脚本不受影响。
   `AuthToken` 字段**故意没有 Validate 规则** —— 空值是合法状态，不是漏配。
2. **配置值 TrimSpace、请求头不TrimSpace**：
   env 手抄易带尾随空格，配置侧必须 `TrimSpace`（否则配了却永不匹配）；
   但请求头若也TrimSpace，`"s3cr3t " == "s3cr3t"` ⇒ 凭空放宽了 token 字符集。
   两侧口径必须不对称，这是单测「尾部多一个字符应被拒」抓出来的。

### 9.4 判据自证失效（本批踩到，值得记）

初版真二进制验收用 `status == 200` 判「带正确 token 放行」。**变异测试证明那是恒绿** ——
摘掉命中分支的 `next.ServeHTTP` 后，Go 的 `ResponseWriter` 默认就是 200 + 空 body。
改判「200 **且响应体能解析出 `alerts` 与 `count`**」后，变异版立即变红、正常版全绿。

同一轮还踩到反向的**假红**：`/healthz` 成功时返回纯文本 `ok`，而判据写了 JSON 解析 ⇒
**正常版也会红**。修法是判「body 非空」而不是判「body 是某种编码形式」。
两条合起来是同一句话：**判据要问「不变量是什么」，别拿实现细节当判据。**
