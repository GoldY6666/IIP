### 实测 4 — worker 心跳 + 优雅退出（对应 §3 第 8 条）

```json
{"time":"2026-09-25T18:38:33.519+08:00","level":"INFO","msg":"worker 已连接 PostgreSQL","poll_interval":1000000000}
{"time":"2026-09-25T18:38:33.536+08:00","level":"INFO","msg":"worker 启动","poll_interval":1000000000}
{"time":"2026-09-25T18:39:33.536+08:00","level":"INFO","msg":"worker alive, poll_count=59","poll_count":59,"in_flight":1}
{"time":"2026-09-25T18:39:40.537+08:00","level":"INFO","msg":"收到退出信号，进入 drain","in_flight":0,"timeout":15000000000}
{"time":"2026-09-25T18:39:40.537+08:00","level":"INFO","msg":"drain 完成，worker 已干净退出","poll_count":67}
```

- **心跳**：18:38:33 启动 → 18:39:33 输出 `worker alive`，间隔精确到 **60s**，符合 `heartbeatInterval = 60 * time.Second`
- **轮询**：67 轮 @1s 间隔，`poll_count` 单调递增，循环稳定
- **优雅退出**：退出信号 → `进入 drain` → `drain 完成，worker 已干净退出`。
  退出方式为向进程组投递 `CTRL_BREAK_EVENT`，证明 `signal.NotifyContext(ctx, os.Interrupt, syscall.SIGTERM)`
  在 Windows 上确实能收到信号并走完 `ctx.Done()` → `drain()` 路径，**未被强杀**（若是强杀则不会有 drain 日志）

## 五、两个待技术负责人拍板的开放项

### 1. `.editorconfig` 的 `[*.ps1] charset = utf-8-bom`

背景：两个 `.ps1` 原本无 BOM，Windows PowerShell 5.1 会按 ANSI 解析 UTF-8 中文，导致**脚本根本无法执行**（报假错）。运维加 BOM 修掉了真实问题，但这属于**对规格外配置的自作主张**。

两条路：
- **接受 BOM**（我倾向）：脚本内可继续用中文提示
- **拒绝 BOM**：需要把 `scripts/pre-commit.ps1` 与 `scripts/tasks.ps1` 内**全部中文字符串去掉**，改为英文提示

→ **我不替你决定，保留给你定。**

> **2026-09-25 补充实证**：本轮验收中，AI 自己重写了 `pg_init.ps1` 并踩到**同一个坑**——
> 用 Write 工具落盘的 `.ps1` 无 BOM，PowerShell 5.1 按 GBK 解析，中文乱码导致脚本
> 报 `“(”后面应为表达式`、`字符串缺少终止符` 等一连串假错。补 BOM 后立即正常。
> 这从反面支持了「接受 BOM」这条路：**只要项目里还有带中文的 `.ps1`，BOM 就是必需品。**

### 2. `docs/decisions.md` 的 ADR-001~004 状态

四条决策（VARCHAR+CHECK 替代 ENUM / 不分区 / TIMESTAMPTZ / feedback 预留表）目前全部标注「待人工确认」。你的裁决「3 处规格外追加全部保留」已覆盖其中部分，但 ADR 文件本身的状态字段还需你确认后改为「已确认」。

## 八、本轮新发现并修复的真实缺陷

| # | 缺陷 | 影响 | 处置 |
|---|------|------|------|
| 1 | `.golangci.yml` 的 `errcheck.check-blank: true` | 4 处误报：`defer func() { _ = src.Close() }()` 等官方推荐写法被判违规，`golangci-lint run` 必红 | 改为 `check-blank: false` + `exclude-functions` 白名单（`(io.Closer).Close` 等） |

**⚠️ 本机沙箱环境的重要约束（M1 必读）**：
在本机自动化执行环境下，**任何后台守护进程都无法跨工具调用存活**——命令返回时整个进程树会被
`TerminateProcess`，`postgres.exe` 甚至来不及写一条关闭日志（这是硬杀的特征，区别于优雅关闭）。
`DETACHED_PROCESS` / `CREATE_NEW_PROCESS_GROUP` 也无效。
因此**需要数据库的验收必须写成单次一体化脚本**（PG 作为该脚本的子进程，脚本内跑完全部依赖 DB 的步骤）。
参考实现：`D:\_iip_setup\rt_all.py`、`D:\_iip_setup\rt_downup.py`。
