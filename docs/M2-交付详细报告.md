## 5. 技术设计要点与对计划的偏离

### 5.1 配置读取：**每轮读一次，未用 TTL 缓存**

手册 §4.4 允许「每次 Correlate 前读一次（或 60 s TTL 缓存）」二选一。实际选**每轮读**。
理由：热生效的证据必须干净——若加缓存，容器内那条对照实验就可能因为「恰好命中缓存」
而失败，反而需要额外解释。当前规模（1000 条回放 466 ms）下多一次查询的代价可忽略。
**RISK-M2-4（缓存导致改后不生效）由此从根本上不存在**，而不是「用测试锁住」。

### 5.2 评分出口量化 6 位小数（ADR-008）

实现期发现：默认 `merge` 阈值 0.80 与「时间 1 + 服务 1 + 标签 1 + 历史 1」的**数学结果恰好相等**，
但 IEEE 754 下 `0.25 + 0.25 + 0.20 + 0.10` 算出 `0.7999999999999999`（少 1 ulp），
于是数学上恰好达阈、按 V1.0 §5.3 的 `>=` 语义应判 MERGE 的组合**被误判为 REVIEW**。
已在 `CalculateScore` 出口统一量化到 6 位小数，并由 `TestCalculateScoreThresholdBoundary`
钉死该边界（该用例同时断言**未量化**的原始浮点值确实低于阈值，防止后人删掉量化后
以为测试多余）。

### 5.3 对计划的偏离

### 10.2 容器部署下「依赖维」恒为 0 —— **已闭合（2026-10-01，M3 前置 L2）**

> **本项已修复。** 方案与取舍见 `docs/decisions.md` **ADR-013**；
> 修复后容器链路 **32 项断言 0 失败**（`D:\_iip_setup\_verify_images_l2.txt`）。
> 下面保留修复前的原始记录，用于追溯这个「静默降级」是怎么被找出来的。

- `config/topology.yaml` 在仓库中有实际内容（frontend / checkout / payment / mysql）。
- 但 `Dockerfile` 只 `COPY cmd/ internal/ migrations/`，**没有 `config/`**；
  `deploy/docker-compose.yml` 也未挂载该文件，且未设 `IIP_TOPOLOGY_FILE`。
- 后果：容器内默认路径 `config/topology.yaml` 不存在 → `LoadYAML` 返回空拓扑
  → `DependencySimilarity` 恒 0。**容器日志已给出 WARN 佐证**：
  `服务拓扑为空，依赖相似度将恒为 0`（`topology_file: config/topology.yaml`）。
- 影响面：宿主直接运行（仓库内有该文件）不受影响；Replay 与 `topology_test.go` 覆盖了
  依赖维的正确性。但**容器形态部署下五维实际退化为四维**。

**危险点不在缺文件本身，而在它静默降级**：`LoadTopology` 对「文件不存在/为空」按设计
返回空拓扑且**不报错**（手册 §4.5 的要求），于是容器内所有既有断言**仍然全绿**——
异常被伪装成了正常。量化差异：跨服务直连边（checkout↔payment）的关联分在**有**拓扑时为
**0.7133**，**无**拓扑时上限只有 **0.5333**（直接掉进 REVIEW 档），原断言集合区分不出来。

- **已实施的修法**（原候选 2）：`deploy/docker-compose.yml` 的 `iip-server` 增加
  `volumes: [../config:/config:ro]`，并用 YAML 合并键在共享锚点之上**追加**
  `IIP_TOPOLOGY_FILE: /config/topology.yaml`。只往 server 追加，**不写进 `*app-env`**
  （拓扑只在 `newRouter` 里被 server 读取）。与另一候选（`Dockerfile` 增加
  `COPY config/ ./config/`）的取舍理由完整见 ADR-013。
- **新增的可判定断言**（`scripts/verify-images.py` 4.5.10）：① 容器日志出现「服务拓扑已加载」
  且 `services` 计数 ≥4；② 跨服务直连边告警对的分数落在 **[0.70, 0.73)**。
  该区间能把「拓扑已加载」与「静默降级」区分开（后者上限 0.5333），故是判据而非「看起来更高」。
- **仍须向使用方明示的两点**：① 容器不再自包含——部署时必须提供 `config/` 目录，
  缺失时行为与修复前完全相同（仍静默降级）；② 被挂载的仍是**示例拓扑**（4 个服务），
  不是任何真实环境的拓扑，生产部署须替换。
